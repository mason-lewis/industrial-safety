# Review suggestions, validate detection, and train

Open **Labeling**, or **Label & train detector** from Monitoring. Create a learning project with the exact object classes you need. A person-only project is supported; forklift is no longer mandatory. Retain every class your deployment needs when fine-tuning replaces the pretrained category set.

1. **Choose footage.** The intake browser lists videos recursively from `data/cv-intake/incoming/`, including the supplied collection. Select a clip and use **Import with automatic grouping**. The list initially shows development footage. The app suggests Training for supplied train/unspecified clips, Validation for supplied validation clips, and Held-out test for supplied test clips. The plain-language role menu explains whether the footage teaches the model, checks improvements, or supplies the final test. Group names are optional under Change grouping if you know a recording session. Automatic groups organize the collection by role, without guessing independent sessions or using behavior categories. Before freezing, review recording separation once; new imports or changed assignments invalidate that review. Import copies its bytes into the learning workspace and preserves the original. The supplied `test` partition cannot be reassigned through this intake workflow. Training footage can supply validation recordings when their independence is established; the app does not infer independence from names. Upload remains available for other local footage.
2. **Sample frames.** Use Prepare frames and AI boxes in batches. Choose whole-clip coverage (default), a time interval, or every decoded frame; choose all clips or one clip, then Sample N clips. Whole-clip coverage spreads the cap across the recording. Sampling appends new timestamps and preserves existing labels; every-frame mode advances through unsampled frames. Limits are 200 new frames per clip per request and 1,000 per project. Include difficult conditions and quiet negative footage. Recording groups keep related clips in one split. Exact copies of analysis-library footage and sources already in learning projects are refused.
3. **Review suggested objects.** By default, opening a new unlabeled frame runs the currently selected local RF-DETR detector. You can disable automatic suggestions or request them explicitly. Each frame retains one proposal set, scores, image hash, model provenance, and unsupported-class warnings. A detector error leaves human labeling available. Proposals never mark a frame reviewed.
4. **Accept, reject, adjust, and add.** Accept correct boxes. Reject wrong boxes. Select Adjust, drag the box or resize its lower-right handle, change its class, or edit percentage bounds. Add missed objects by drawing or using **Add missed object**. Undo retains box/decision state. Save a draft to pause. **Save review & next** requires all proposal decisions to be resolved; **Accept remaining & next** explicitly accepts the remaining visible suggestions and advances to the next unreviewed frame in the selected role. Both require you to inspect for objects the detector missed. An empty reviewed frame requires explicit whole-frame confirmation, even after rejecting every suggestion.
5. **Add classes when needed.** Open Object classes and edit the comma-separated names before freezing. Adding/changing classes reopens frame review, clears verified-empty attestations, and retains prior review history. Classes referenced by boxes or proposals cannot be removed. The existing model cannot propose a new class it was not trained for; use AI image review or add those boxes manually until a trained detector supports them.
6. **Check detection quality.** After reviewing Validation frames, run **Check current detector on validation frames**. The report uses the first 25 reviewed validation frames by default (API cap 100), one confidence threshold, and one-to-one score-ordered box matching at IoU 0.5. It shows per-class precision, recall, misses, and false detections, with links back to example frames. Missing denominators remain null. The report retains frame image hashes, model provenance, and a label snapshot hash; changed validation labels trigger a rerun notice. This is a development check, not mAP, a held-out test, or a camera-wide accuracy claim. Camera registration, representative sampling, and sustained throughput benchmarks need separate work.
7. **Freeze reviewed labels.** Every frame must be reviewed, recording groups must not cross splits, and every chosen class needs reviewed examples in training, validation, and test. Only final human-reviewed boxes enter COCO exports; proposal scores, rejected boxes, source titles, and behavior labels do not become training annotations. Frozen snapshots and class names remain immutable. Archive excludes an accidental clip while retaining its bytes and labels.
8. **Train, evaluate, and deploy.** Choose Nano or Small, device, epochs, and batch size, then explicitly start training. The subprocess receives only train/valid files and uses `run_test=False`. Select the checkpoint from validation results before **Evaluate held-out test & seal training**. Test evaluation locks its checkpoint hash and prevents further training on this project. Registration requires completed evaluation and a declared license; activation is separate and checks compatibility. No training launches from an import, a label correction, or a validation check.

## Blind review and metadata boundaries

Original titles, folder paths, supplied behavior categories, and group metadata stay in provenance/source preparation. The intake browser uses neutral video IDs by default; folders organize the intake list and original filenames are optional. Source preparation is collapsed once frames exist; clip rows use neutral IDs, with names inside a collapsed provenance panel. Object review shows neutral clip IDs, source position, and split, without titles or behavior labels. The local detector receives image arrays only. Source categories never infer an object class, a box, or a safety result. Pixel dimensions are used to normalize box coordinates, not as class evidence. COCO filenames are neutral generated IDs.

The supplied collection contains 691 MP4 videos (566 in train and 125 in test), about 10 GB, plus its README. No object-box annotation files were found in the intake. Three inspected clips decode as H.264 at 1920×1080 with PTS; their measured average rates are about 24.8 FPS. These are checks of those clips, not a complete camera/session or annotation audit. Behavior folder labels are not object-detection ground truth.

This prevents metadata entering inference or scoring, but cannot remove visual cues burned into footage or undo expectations a human already learned. Labelers must inspect the whole image, especially missed objects. Using detector-assisted annotations without correcting omissions can inflate the same detector's apparent accuracy. An independent labeling pass for final test data is recommended.

## Isolation and recovery

Sources, images, proposals, final labels, review/class history, validation reports, frozen snapshots, and jobs live under `data/learning/<project-id>/`. Old project JSON parses without new fields; revisions begin at zero. Concurrent stale review saves fail instead of overwriting a newer save. Existing proposals and corrections cannot be replaced by repeatedly requesting assistance. The local assistance service serializes inference and joins native work on request cancellation.

Related/re-encoded footage still needs honest recording-group assignment; hashes cannot discover every duplicate or prove independence. Human approval does not verify annotation truth. Reviewed examples in each split do not establish adequate sample size or deployment coverage. Frozen integrity checks, independent final testing, and explicit deployment decisions remain necessary.

The local detector assistance makes no hosted call and uses no new agent framework. It may load/download missing detector assets on an explicit or automatic suggestion request. The separate PydanticAI annotation assistant still has its bounded tools and paid/media guards; it runs only through the hosted image controls or explicit AI batch, and cannot approve labels, train, or promote a model. Batch active learning and autonomous training/deployment remain unimplemented.

See the [trainer guide](../README.md), [intake guide](../../../../data/cv-intake/README.md), and [industrial guide](cv-industrial.md).

### Image review with AI

Under Step 2, expand **Enable hosted image review**, set a conservative per-image cost allowance, and click **Enable AI image review**. This saves an operator allowance for the learning workflow; it is not a verified provider price. Backend paid opt-in, API key, valid token rates, spending limits and the stop switch still apply. Other hosted image workflows retain their existing rates.

Click **Review image with AI** to inspect the image for every project object class and review saved/candidate boxes. The annotation assistant returns accepts, rejects, corrected boxes, uncertain cases and missing-object boxes. Add `pallet` to Object classes if required; `pallet jack` denotes a different object. No new class is added automatically.

Fresh AI drafts for unreviewed frames load directly into the editor. Already-reviewed frames keep the explicit **Use AI draft** control. Adjust or remove boxes, add missed objects, and **Save review & next**. Saving is your confirmation that the frame is completely labeled. An AI recommendation never approves labels by itself; rejecting all boxes still requires the human verified-empty checkbox. Existing human labels remain saved until you explicitly save your edited draft. Saving records the AI run reference with human review history.

Enable **Review new frames with AI automatically** to review each new unreviewed frame as you navigate. This setting starts hosted calls and is off initially. It runs one frame at a time, after local suggestions when enabled, and stops retrying a failed frame automatically. Revisit or use the explicit review button for a retry. It does not process a background backlog, train, or deploy. Reviewed frames require an explicit AI review click.

The model receives only a freshly re-encoded image with its longest side at most 1024 pixels, exact class names, and candidate IDs/labels/normalized box coordinates. It receives no title, filename, directory, source category, dataset role, recording group, score, or timestamp. It gets no metadata tools. Candidate labels are hypotheses, not ground truth. The original image and existing proposals remain intact. Results preserve input/image hashes, model/prompt audit and history. Identical inputs at the same label revision reuse a saved result; label/class/image changes require a new review. Invalid outputs, stale inputs, provider failures and cancellation never replace human labels.

AI localization and completeness need measurement on real footage. Inspect boxes and missed instances independently, especially on validation/test footage. Fixture checks establish plumbing, not recognition accuracy.

### Select multiple sources by folder

Open Step 1 and choose a folder or **All folders**. Check individual files, **Select this page**, or **Select available files in this folder** / **Select all matching files**. The selected count carries across pages and folders. Use **My selected files** to inspect the batch, or **Clear selection** to start again. Already-imported files are green, cannot be selected twice, and show the current project's role and reviewed/sample counts; files imported in another project are also marked. Refresh intake after outside changes.

Choose **Recommended role for each file**, Training, Validation or Test, then click **Import N selected videos**. Supplied test files always remain held out. Import runs sequentially with progress; **Stop after current file** preserves completed copies. Failed/unstarted files remain selected and individual errors stay visible. Leaving the learning screen stops further submissions after the current file. Sample the newly imported clips afterward. No sampling, AI review, or training starts merely from importing.

Folder names only organize the source list. Filename display is optional. AI and detector inputs exclude folders, titles and behavior categories, and training uses neutral image names and human-approved object labels. Select varied recordings rather than assuming a folder name proves object presence or recording independence.

### Inspect the agent and audit

**What the AI is doing** shows persisted stages and updates every two seconds during image review. Select an earlier **Review run** to inspect successes, failures, blocked requests or saved-result reuse. Expand **Model requests, responses, tool calls and audit events** for actual observable request/output, validation, retry, usage and error records. **Download this review audit** exports the full redacted NDJSON trace.

The annotation assistant uses scoped tools to decide existing candidates, add missing objects, replace/correct its additions, and inspect its draft. Tool edits are run-local recommendations, never human approvals. The activity panel counts actual tool events; structured-output calls are excluded. Hidden reasoning and credentials are excluded. Token/cost reporting arrives after model responses; unknown charges are retained and shown as unresolved. Imports and human saves using an AI draft also write persistent audit events. Interrupted reviews keep their history and require an explicit retry.


Use **Prepare AI drafts for N frames** to let the agent prepare boxes before you review. It skips human-reviewed frames and saved drafts at the current label revision. Choose the clip scope, dataset role in Step 2, and a frame cap (25 by default, at most 100). This is a paid operation after image review setup. Progress updates after each frame; errors or budget blocks stop the batch without automatic retries. Stop after current item, leaving the screen, or closing the browser prevents subsequent submissions. Completed drafts and audit traces remain saved. Use **Review N ready AI drafts**, check each canvas, reject/adjust any mistake, then **Save review & next**. Empty frames still require the explicit checkbox. This reduces drawing work; human review and model training remain separate.
