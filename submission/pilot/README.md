# Operator evidence and small pilot

**No measurement in this folder is completed evidence unless a human records it.** The app's fixture mode is only a demonstration. Do not ask a model to invent missing labels, timings, feedback or measured provider costs.

1. Obtain the safety/operations contact's agreement to take part and to quote anonymized feedback. Use a participant code. Explain that this tool suggests concerns for review, does not certify safety and cannot control equipment or send messages.
2. Before showing model output, independently label the 24 neutral candidate clips. Use `label-and-time.html` locally. For each category record visible conditions, exact time bounds, occlusion and ambiguity. Do not show `demo/provenance.json` to the labeler; it reveals source behavior names. Review source grouping; keep related clips together. Do not use this held-out set to tune prompts. If it cannot provide eight positive, eight negative and eight ambiguous clips, collect additional licensed footage and document gaps rather than relabeling it to fit.
3. Have a second reviewer check disagreements if available. Otherwise identify the single-labeler limitation. A source behavior tag is not a hazard annotation. The person who develops prompts should not silently become an independent labeler.
4. Use matched source pixels, windows, question, PPE/site context, model and $0.15 cap. For the screening-only baseline submit `review_strategy=full, escalate_to_safety_team=false`. For the full workflow set the latter true. Both use `mode=hosted`, with `./start --allow-hosted` and the existing API key. This is an explicit **operator-run** step. Never raise the $2/day or $20/month caps to finish the experiment; partial runs and pending reviews are outcomes. Forty-eight runs at the maximum cap would cost $7.20 and require at least four budget days. Actual spend may be lower, but do not promise completion before the deadline at the maximum rate.
   The optional operator command is `python scripts/run_course_pair.py --source clip-001.mp4 --allow-paid`. It runs exactly one pair and writes reports/audits under `data/artifacts/course-runs/`. It is never part of offline verification. Stop the background review worker before using this direct executor to avoid duplicate dispatch.
5. Export JSON/HTML plus the authorized audit trace from each run. Keep the version/package hash and provider invoice separately. Unknown request charges block automatic replay. Reconcile only with provider evidence. Do not claim that calculated usage is a billed invoice.
6. For the user trial, divide comparable held-out tasks into sets A and B with similar duration and category mix. Alternate the order across participant codes: odd participants do A manually then B assisted; even participants do A assisted then B manually. Never show the same clip twice to one participant and treat the second viewing as independent. With only one participant, counterbalance task blocks and report the order/learning confound. Use equal written tasks: identify concerns, cite time/evidence, propose next action and state uncertainty.
7. Record actual start/stop times, corrections, useful findings, false alarms, missed conditions, confidence and feedback. The form timer is a convenience, not a hidden measurement. Record interruptions. Compare median per-task time and correction counts with individual results. A small convenience pilot does not prove reduced injuries, enterprise productivity or statistical generalization.
8. Score exported reports with `python scripts/evaluate_course.py --labels human-labels.json --baseline baseline/*.json --full full/*.json --output submission/evidence/evaluation.json`. It refuses fixture results and unmatched inputs/configurations. Temporal matching is deterministic one-to-one, highest overlap first, IoU ≥0.5. Review the failure IDs and retain representative false positives, misses, abstentions and ambiguous cases with images. Do not report false alarms per camera-hour from selected short clips.
9. Update `report.html` and `slides.html` through `scripts/build_course_artifacts.py`, preserving pending labels for anything not measured. Attach results and reviewed quotes to the evidence record. The builder currently reports measured engineering evidence and clearly marks open product evidence; it never turns projections into observations.

## Required files from real runs

- `hosted-runs/`: paired exported JSON/HTML, audit traces and version identifiers.
- `human-labels.json`: independent labels, reviewer code, source groups and rationale.
- `pilot-results.json`: anonymized raw task times, errors, corrections, consented feedback and protocol deviations.
- `billing-reconciliation.json`: reported tokens, cached/write categories, request IDs, service tiers, pricing version, calculated usage and any verified billed cost. Keep secrets out.
- Failure gallery: exact retained pixels and temporal match outcomes. No curated success-only examples.
